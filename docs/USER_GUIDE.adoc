= adocLIVE User and Contributor Guide

A full-featured AsciiDoc editor plugin for https://joplinapp.org/[Joplin] with real-time live preview, rendered preview modes, a ribbon-style toolbar, and rich block editing. Write AsciiDoc notes with the same visual feedback you'd expect from a modern word processor -- rendered headings, media, tables, code blocks, diagrams, math, and more appear inline as you type.

Requires *Joplin 3.1+* (desktop only). The plugin ID is `com.asciidoc.joplin-plugin`; the npm package is `joplin-plugin-adoclive`.

== Features at a Glance

* *Live preview* -- AsciiDoc renders inline as you type, powered by CodeMirror 6, with split/raw/rendered preview modes rendered through Asciidoctor.js
* *Ribbon toolbar* -- four tabbed panels (Text, Insert, Advanced, View) with one-click access to common AsciiDoc structures, formatting, media, references, and editor controls
* *Block editing* -- click rendered tables, code blocks, images, audio/video blocks, diagrams, blockquotes, and other supported blocks to edit them in focused overlays or inline
* *Markdown conversion* -- convert existing Markdown notes to AsciiDoc with a single command
* *Wiki-links & cross-references* -- `+<<noteId,Display Text>>+` links to other notes in the current Joplin notebook with autocomplete
* *Joplin include support* -- `+include::joplin:<note-id>[]+` and `+include::resource:<resource-id>[]+` directives expand in rendered preview with target autocomplete
* *Author line* -- author name and email rendered as a byline under the document title, with implicit attribute generation
* *Attribute autocomplete* -- type `+{+` to autocomplete document attributes defined in the header
* *Template system* -- save and reuse note templates, plus persistent snippet templates with `@@` inline autocomplete
* *Spellcheck* -- nspell-based spell checker with personal dictionary support and a Joplin/Electron native fallback
* *Mermaid diagrams* -- 24 diagram types rendered inline with live preview editing
* *Math rendering* -- inline and block `+stem:+`, `+latexmath:+`, and `+asciimath:+` content rendered with KaTeX
* *Media handling* -- insert, paste, or drop images, audio, and video; local files are attached as Joplin resources
* *Table of Contents* -- automatic TOC generation from document headings
* *Bibliography* -- citation management with 10 format presets (APA, MLA, AMA, Chicago, Turabian, IEEE, Vancouver/NLM, Harvard, ASA)
* *Snippet Templates* -- save named text snippets with Cmd/Ctrl+Shift+C, insert with Cmd/Ctrl+Shift+V or by typing `@@`
* *Find & replace* -- custom editor search with match counts, replace, regex, case/word toggles, and find-in-selection
* *Text case transforms* -- cycle through UPPER, Title Case, lower, snake_case
* *Smart quotes* -- automatic curly quote insertion with prime/double-prime support
* *Editor themes* -- follow Joplin's theme or choose Light, Dark, Sepia, High Contrast, or Midnight

'''

== Getting Started

=== Installation

. Install dependencies and build the plugin:
+
[source,bash]
----
npm install
npm run build
----
. Install the generated `publish/com.asciidoc.joplin-plugin.jpl` file in Joplin, or run `npm run deploy:joplin` to build it, copy it into existing local Joplin desktop profile plugin folders (`~/.config/joplindev-desktop` and/or `~/.config/joplin-desktop`), and clear the plugin cache.
. *Restart Joplin* (Cmd+Q / Ctrl+Q, then reopen) -- plugins only load on startup.

=== Creating an adocLIVE Note

To have all new notes created as adocLIVE notes by default, enable *"Create new notes as adocLIVE"* in *Preferences > adocLIVE*.

You can also convert existing notes or create adocLIVE notes on demand:

* *Tools > New adocLIVE Note* -- creates a blank adocLIVE note
* *Tools > Convert to adocLIVE Note* -- converts the current Markdown note in place
* *Tools > Convert to adocLIVE Note (new note)* -- creates an adocLIVE copy, keeping the original
* *Tools > Edit AsciiDoc Attributes* -- edits plugin-managed Asciidoctor attributes stored in the note's adocLIVE settings block
* *Right-click a note > Create adocLIVE Copy* -- convert or copy from the note list; multi-note selections are supported
* *Right-click a note > Replace with adocLIVE Note* -- convert in place from the note list; multi-note selections are supported
* *Note toolbar button: "Make adocLIVE"* -- one-click convert for the current note

=== Converting Entire Notebooks

* *Right-click a notebook > Create adocLIVE Copy of Notebook* -- recursively copy the notebook tree to a new notebook named `+<original notebook> (adocLIVE)+`, converting non-adocLIVE notes along the way
* *Right-click a notebook > Replace with adocLIVE Notebook* -- recursively convert non-adocLIVE notes in the notebook tree in place

== Live Preview

The editor renders AsciiDoc constructs inline as you type. Move your cursor to a line to see and edit the raw markup; move away and it renders as preview.

=== Supported Constructs

*Headings* -- `+= Title+` through `+====== Level 5+`, rendered with decreasing font sizes, section numbering, TOC entries, and section IDs.

*Author line* -- A line directly after the document title (`+= Title+`) in the format `+Firstname Lastname <email>+` is parsed as the author line. It renders as a byline under the title heading ("Author Name -- email") and automatically sets the `+{author}+`, `+{firstname}+`, `+{lastname}+`, `+{middlename}+`, `+{authorinitials}+`, and `+{email}+` document attributes.

*Text formatting* -- Bold, italic, monospace, strikethrough, superscript, subscript, underline, overline, highlight, and color/size roles all render inline.

*Lists* -- Bullet (`+*+`), numbered (`+.+`), checklists (`+* [x]+`), and definition lists (`+term::+`) with multi-level nesting, ordered list styles (`+[lowerroman]+`, `+[upperalpha]+`, `+[lowergreek]+`), `+start+`, `+%reversed+`, interactive checklists, and horizontal description list sizing. Select multiple list items and press Tab/Shift+Tab to indent/dedent them together.

*Code blocks* -- Fenced source/listing blocks with syntax highlighting, language labels, `+:source-language:+`, shorthand attrlists such as `+[%linenums,ruby]+`, IDs, roles, `+opts+`, `+nowrap+`, `+start+`, and highlighted-line metadata. Click to edit in a modal with a language selector.

*Tables* -- Full rendered table with header row/column support, `+opts+` aliases, table roles, column and cell alignment, row/column spans, nested AsciiDoc cells, literal cells, striping patterns, frame and grid options. Click to edit with add/remove row/column controls and header toggles. Supports scale and alignment settings.

*Images* -- Web URLs and Joplin local resources (`+:/resourceId+`). Supports alt text, title, caption, positional or named pixel/percentage width and height, alignment, float, roles, `+imagesdir+`, links, window targets, link options, and caption position. Click to open a full image editor modal.

*Audio and video* -- `+audio::+` and `+video::+` block macros render as editable media blocks. Local files inserted from the toolbar, clipboard, or drag-and-drop are attached as Joplin resources. Video supports local files, direct remote URLs, YouTube, and Vimeo; audio supports local files and direct remote URLs.

*Admonitions* -- NOTE, TIP, WARNING, CAUTION, and IMPORTANT blocks with colored labels.

*Blockquotes* -- Rendered with attribution. Click to edit content and author.

*Table of Contents* -- Add `:toc:` to the document header to generate a clickable Table of Contents from section headings. Supports `:toclevels:` (1-5, default 2), `:toc-title:` (custom title), section numbering, `+idprefix+`, `+idseparator+`, and three placement modes: `auto` (after header), `preamble` (after preamble), and `macro` (at `toc::[]` location). Click any TOC entry to jump to that heading.

*Mermaid diagrams* -- `+[mermaid]+` blocks render 24 diagram types inline: Flowchart, Sequence, Class, State, ER, Gantt, Pie, User Journey, Git Graph, Mindmap, Timeline, Quadrant, Sankey, XY Chart, Block, Packet, Kanban, Architecture, C4 (Context/Container/Component/Deployment), Requirement, and ZenUML. Click to edit in a dedicated modal with live preview. Supports scale, alignment, and theme switching.

*Footnotes* -- Auto-numbered superscript references [1], [2], [3]. Named footnotes (`+footnote:id[text]+`) share numbers when referenced. Click to see a floating popup with the footnote text.

*Cross-references* -- `+<<noteId,Display Text>>+` and `+xref:target[text]+` render as clickable links. Joplin note references can use note IDs or exact note titles in the active notebook. Xrefs with section anchors (`+<<noteId#section,text>>+`) include a toggle to preview the linked section inline.

*Math / STEM* -- Inline math via `+stem:[]+`, `+latexmath:[]+`, or `+asciimath:[]+` macros renders via KaTeX directly in the preview. Display-mode block math uses `+[latexmath]+` / `+[asciimath]+` / `+[stem]+` attribute followed by `+++++` delimiters. The `:stem:` document attribute controls the default notation. AsciiMath expressions are auto-converted to LaTeX before rendering. Click a rendered block equation to edit in a modal with live preview, notation selector, scale (10-200%), and alignment.

*Element attributes* -- Role/attribute lines like `+[.text-center]+`, `+[role=text-center]+`, `+[#id.role%option]+`, and `+[opts="a,b"]+` are hidden in preview but automatically revealed for editing when the affected line is clicked.

*Collapsible blocks* -- `+[%collapsible]+`, `+[%collapsible%open]+`, and paragraph-form `+[example%collapsible]+` blocks render with a clickable caret to expand/collapse.

*Sidebar & Example blocks* -- Rendered with appropriate borders and backgrounds.

*Horizontal rules & page breaks* -- `+'''+`, Markdown-style thematic breaks, and `+<<<+` render as dividers or labeled page/column breaks, including roles and options such as `+[.column%always]+`.

*AsciiDoc text replacements* -- `+(C)+` becomes (C), `+->+` becomes ->, `+--+` becomes an em dash, `+...+` becomes an ellipsis, and more.

*Attribute references* -- `+{name}+` references are resolved against built-in AsciiDoc attributes, author-line attributes, document header attributes, body attributes, and unset attribute entries such as `+:!name:+`.

*Include directives* -- `+include::...[]+` lines remain visible in inline Live Preview for editing. In Split View and Rendered AsciiDoc Preview, adocLIVE expands supported Joplin note/resource includes before handing the document to Asciidoctor.js.

For canonical Asciidoctor output, use the split/preview modes. Those render through Asciidoctor.js in the plugin sandbox; Live Preview is an inline editor approximation designed for low-latency editing.

== Wiki-Links & Autocomplete

Type `+<<+` to trigger Joplin note autocomplete -- recent notes from the current Joplin notebook appear immediately, and results filter as you type. Bibliography entries from the current note are also shown in a separate group. Select a note to insert a cross-reference link.

After selecting a note, type `+#+` to drill into its sections. The autocomplete shows heading levels (h2, h3, etc.) with indentation, letting you link directly to a specific section.

Type `+{+` to trigger document attribute autocomplete -- all attributes defined in the document header (including implicit author attributes) appear in a dropdown. Selecting one inserts the attribute name with a closing `+}+`.

Type `+@@+` to trigger snippet template autocomplete -- all saved snippets appear in a dropdown, filtered as you type. Selecting one replaces the `+@@+` prefix with the snippet content.

'''

== Joplin Includes

adocLIVE can expand Joplin-backed `+include::+` directives in Split View, Rendered AsciiDoc Preview, and rich-text clipboard rendering. Type `+include::+` to autocomplete supported include targets.

[cols="1,3"]
|===
| Include target | Behavior

| `+include::joplin:<note-id>[]+`
| Includes another adocLIVE note by Joplin note ID

| `+include::<note-id>[]+`
| Includes another adocLIVE note by bare note ID

| `+include::<exact note title>[]+`
| Includes an adocLIVE note by exact title match

| `+include::resource:<resource-id>[]+`
| Includes a text-like Joplin resource attachment. AsciiDoc resource files are stripped of their adocLIVE settings block before expansion.

| `+include:::/<resource-id>[]+` or `+include:::<resource-id>[]+`
| Includes a text-like Joplin resource using the Joplin resource-reference form
|===

Supported include attributes:

* `+lines=1..10;15+` -- include selected lines; `+-1+` means the last line
* `+tag=name+` or `+tags=name;other+` -- include tagged regions; `+tags=**+` removes tag directive lines
* `+leveloffset=+1+`, `+leveloffset=-1+`, or an absolute numeric level offset -- adjusts included headings
* `+indent=2+` -- normalizes the included block and re-indents it
* `+opts=optional+` -- suppresses the missing-include warning block

Missing non-optional includes render as WARNING blocks. Cyclic note/resource includes are detected and skipped with a warning.

== Templates & Snippets

=== Note Templates

. Open any AsciiDoc note you want to reuse as a template.
. Use the *Template* button in the Insert tab (Templates section) and choose *"Assign Note as Template"*.
. The note is tagged with `asciidoc-template` and appears in the template library.
. To insert a template, click *Template*, search by title, and click to insert its content at the cursor.
. To remove a template, click the *x* button next to its name in the template list.

=== Snippet Templates

Persistent named text snippets for frequently reused content (signatures, boilerplate, macros):

* *Save a snippet* -- select text and press *Cmd+Shift+C*, or right-click and choose *"Copy as Snippet Template"*. A prompt appears to name the snippet (press Enter with an empty name to auto-generate one from the content).
* *Insert via shortcut* -- press *Cmd+Shift+V* to open an autocomplete dropdown with all saved snippets.
* *Insert via inline trigger* -- type `+@@+` anywhere in the editor to trigger snippet autocomplete. Type after `+@@+` to filter by name. When a snippet is selected, the `+@@+` prefix is removed and replaced with the snippet content.
* *Browse and insert* -- open the *Template* dropdown in the Insert tab to see snippets listed below note templates. Click any snippet to insert it.
* *Manage snippets* -- click *"Manage Snippets"* in the Template dropdown to open a modal where you can rename, edit, or delete saved snippets.
* Snippets persist across sessions -- they are stored in Joplin's plugin settings.

'''

== Markdown Conversion

When converting a Markdown note to AsciiDoc, the plugin automatically converts:

* *Headings*: `+# Heading+` becomes `+= Heading+` (all 6 levels)
* *Unordered lists*: `+- item+` becomes `+* item+`, with nested indentation converted to AsciiDoc nesting (`+**+`, `+***+`, etc.)
* *Links*: `+[text](url)+` becomes `+link:url[text]+`
* *Images*: `+![alt](url)+` becomes `+image::url[alt]+` (block) or `+image:url[alt]+` (inline)
* *Linked images*: `+[![alt](img)](link)+` becomes `+image::img[alt, link=link]+`
* *Inline formatting*: `+**bold**+` becomes `+*bold*+`, `+***bold italic***+` becomes `+*_bold italic_*+`, `+~~strike~~+` becomes `+[.line-through]#text#+`
* *Code blocks*: Fenced code blocks (`++```lang++`) become AsciiDoc listing blocks (`+[source,lang]+` / `+----+`)
* *Horizontal rules*: `+---+`, `+***+`, `+___+` become `+'''+`
* *HTML cleanup*: `+<br>+` tags become newlines, common inline HTML tags are stripped
* *Escape removal*: Markdown backslash escapes (`+\*+`, `+\[+`, etc.) are cleaned up
* Content inside fenced code blocks is left untouched

The same converter is used by *Convert from Markdown & Paste* in the editor context menu.

== Document Attributes & Author Line

Document attributes are key-value pairs defined in the document header (lines starting with `+:name: value+`). adocLIVE recognizes header attributes before the document title, directly after the title/author line, and body attributes that take effect from their source line forward. They can be referenced as `+{name}+`.

An *author line* placed directly after the document title is automatically parsed:

[source,asciidoc]
----
= The Intrepid Chronicles
Kismet R. Lee <kismet@asciidoctor.org>
:toc: auto
----

This sets the implicit attributes `+{author}+`, `+{firstname}+`, `+{middlename}+`, `+{lastname}+`, `+{authorinitials}+`, and `+{email}+`, and renders the author name and email as a byline beneath the document title.

The *Document Attributes* toggle in the View toolbar tab controls whether the attributes block is visible in the rendered preview.

The *Tools > Edit AsciiDoc Attributes* command edits plugin-managed Asciidoctor attributes stored in the hidden adocLIVE settings block at the end of the note. These attributes are passed to Asciidoctor.js when rendering split/preview output; they do not replace the visible `+:name: value+` lines in the note body.

== Architecture

The plugin consists of two webpack bundles copied into `dist/`, then packaged into `publish/com.asciidoc.joplin-plugin.jpl`:

[cols="1,1,3"]
|===
| Bundle | Target | Contains

| `index.js`
| Node (plugin sandbox)
| Plugin registration, commands, settings, IPC handlers, Markdown-to-AsciiDoc conversion, Joplin include expansion, resource handling, Asciidoctor.js rendering

| `panel.js`
| Web (webview)
| CodeMirror 6 editor, live-preview decoration engine, split/raw/rendered view state, KaTeX math rendering, Mermaid diagram rendering with ELK layout, media editors, nspell spellcheck with native fallback, ribbon toolbar, IPC client
|===

AsciiDoc notes are identified by a `++```asciidoc-settings++` sentinel block appended to the note body. This block stores plugin-managed JSON settings such as dialog-managed Asciidoctor attributes and is stripped before editing and rendering.

Communication between the plugin sandbox and the webview editor uses Joplin's `postMessage` IPC protocol for operations like saving, rendering, resource creation/resolution, note search, include target lookup, section lookup, template management, snippet CRUD, spellcheck settings, and fullscreen mode.

'''

Useful orientation points:

* Most editor-facing behavior lives in `+src/lib/editor/live-preview.ts+`, `+src/panel.ts+`, and the toolbar panel files under `+src/lib/toolbar/panels/+`.
* Joplin integration lives mainly in `+src/index.ts+`, including command registration, settings, Markdown conversion, resource handling, include expansion, and Asciidoctor.js rendering.
* Shared parsing helpers live under `+src/shared/+` so tests and runtime code use the same section, link, attribute, note-link, and command-argument logic.
* Macro-specific serialization/parsing helpers live under `+src/lib/utils/+`; these are covered by focused unit tests.
* `+dist/+`, `+publish/+`, and `+node_modules/+` are generated or installed directories. Do not edit them as source.

== Building

[source,bash]
----
npm install        # Install dependencies
npm run build      # Production build -> publish/com.asciidoc.joplin-plugin.jpl
npm run deploy:joplin # Build and copy the .jpl into local Joplin desktop plugin folders
npm run dev        # Watch mode for development
----

Useful verification commands:

[source,bash]
----
npm run test:unit  # Vitest unit suite
npm run typecheck  # TypeScript check
npm pack --dry-run # Confirm npm package contents
----

=== Contributor Test Lab

The Test Lab boots the real panel bundle in pinned Chromium against a deterministic simulated Joplin host. It includes multi-session races, fault controls, replay, scroll/visual/accessibility protection, performance/leak checks, and extracted-JPL smoke coverage.

[source,bash]
----
npm run playwright:install
npm run lab             # Dashboard on http://127.0.0.1:4173
npm run test:lab:pr     # Required automated contributor gate
npm run test:lab:nightly
npm run baseline:review # Review immutable visual/scroll candidates locally
----

See link:test-lab/README.md[Test Lab contributor guide]. Baseline approval and the native Joplin matrix remain explicit human evidence gates.

After every build, restart Joplin to load the updated plugin.

== Publishing

Release preparation and publication are intentionally separate. Direct
`+npm publish+` and the legacy bump/build/publish script are disabled so a
reviewed artifact cannot be rebuilt during publication.

[source,bash]
----
npm run release:prepare  # clean source commit -> canonical immutable bundle
npm run baseline:review  # review 13 visuals, scroll, and native-platform evidence
npm run baseline:apply -- <receipt.json>

# After the separate evidence-only commit, validate without publishing:
npm run release:publish -- \
  --bundle .baseline-candidates/<digest> \
  --receipt docs/test-lab/evidence/baseline-reviews/<digest>.receipt.json \
  --confirm 1.0.4 \
  --dry-run
----

The user creates the clean source commit and the subsequent evidence-only
commit. Removing `+--dry-run+` is a separate explicit publication action: the
command verifies the receipt, live production audit, commit allowlist,
authentication, tags, and exact stored JPL/npm-tarball hashes before pushing or
publishing. See link:test-lab/RELEASE_HANDOFF.md[the 1.0.4 release handoff].
The Joplin plugin directory discovers npm packages carrying the
`+joplin-plugin+` keyword.
